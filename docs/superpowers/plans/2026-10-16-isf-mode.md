# Selectable ISF Generator Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add reliable local ISF generators and microphone-reactive visuals as a separate OSC-selectable mode, with live published parameters and transactional shader changes.

**Architecture:** A pure metadata/parameter/audio layer feeds a bounded background source loader and a main-thread VVISF/VVGL adapter. The existing controller retains active visuals until a candidate has rendered successfully. Application-owned resource accounting and validated immutable sources constrain the upstream runtime without replacing its shader interpreter.

**Tech Stack:** C++17, CMake, SDL2, desktop GL/GLES 3, pinned VVISF-GL, its bundled JSON/exprtk headers, bounded native FFT, Catch2, Python OSC tooling.

**Spec:** `docs/superpowers/specs/2026-10-16-isf-mode-design.md` (approved).

## Global Constraints

- Standalone generators and microphone audio only; no video effects, transitions, browser, second window or audio output.
- VVISF-GL revision `7306b1abdd0b5536f0f230c0519453e79184e08b`; inventory/pin transitive sources and retain license notices.
- Adopt the SDL-owned CGL/EGL context. Do not introduce Qt/GLFW or legacy Broadcom display ownership.
- Default root `/opt/sideshow/isf`; development root `deps/isf`.
- Exact, case-sensitive relative `.fs` IDs; extension discovery is case-insensitive. Optional same-basename `.vs` is not selectable.
- Direct-child folder collections; `playlist .` means root. Ignore hidden entries and symlinks. Validate local source/import paths at open.
- At most 1 MiB each fragment/vertex source, 64 inputs, 8 passes and 16 imported images per shader.
- Imported images at most 4096 per axis and 8,847,360 pixels each. Check decoded-byte arithmetic before allocation.
- Output fits 1280×720 landscape / 720×1280 portrait by default, never above drawable size. Config accepts positive integer axes up to 4096.
- Every target fits GL_MAX_TEXTURE_SIZE and 4096 per axis. Float targets retain requested precision or fail clearly.
- Account all application/runtime textures and pools: 128 MiB per shader instance, 256 MiB across current/candidate ISF instances.
- At most 64 pending parameter/event commands per candidate; discard new arrivals on overflow with a warning.
- Defaults and time/history reset on successful load/mode return; last shader/folder remembered; overrides never persist to disk.
- `isf_param` accepts name plus typed numeric values; `isf_event` accepts name only. Invalid updates are atomic no-ops.
- Missing declared continuous bounds add no artificial normalized clamp. Menu integers require VALUES membership where declared.
- Event true for all passes of one presented frame; preparation must not consume it invisibly.
- Audio waveform silence 0.5, spectrum silence zero; default width 512, positive integer MAX up to 4096, history/FFT window up to 8192 samples.
- Shared duration/shuffle/lock drive selection; beat sensitivity/hardcut remain stored for other modes. Brightness/blackout apply once in main.
- No scan, file/image read or worker join on the render path. GL stays on main; compile/driver work is not preemptible.
- Preserve old picture/state on failed candidate or recoverable parameter/resize update. Invalid newest selections supersede older candidates.
- Startup ISF prepares over MilkDrop fallback. Fatal ISF render failure gets one MilkDrop recovery attempt.
- Core-only builds remain free of SDL/GL/VVISF binary dependencies. Do not alter projectM preset recovery.
- Native execution in an isolated worktree is the preserved preference. One independent whole-branch review; no push/merge without a request.

## Review Focus

1. Rapid mode/shader/parameter/event sequences, including an invalid newest selection, must not activate stale candidates or apply controls to the old shader (Tasks 3, 6).
2. A first-frame event must actually be visible once, including when controls arrive after preparation but before presentation, and must apply to every multipass stage (Tasks 5, 6).
3. Imports replaced by symlinks and dynamic size expressions driven by extreme OSC values must not bypass file containment or allocate before budget checks (Tasks 2, 4, 5).
4. Pending shaders under microphone stalls/reconnects must receive fresh silence/audio without starving the active backend or replaying old spectrum energy (Tasks 3, 6).
5. A compile/allocation/resize failure with dirty GL state must preserve the running picture and release candidate/pool resources; repeat switches must not accumulate memory (Tasks 1, 5, 7).
